# 账号保护机制

本次改动只固定账号身份、控制请求放大，并完善故障隔离。它不复刻官方 TLS 指纹，也不承诺降低上游封号率。

## 固定账号身份

启动加载、后台新增以及凭据更新会在第一次验证或刷新前固定账号级 `machineId`，并随凭据持久化。已有合法账号值继续保留；UUID 按原兼容规则转换成 64 位十六进制形式。缺失或旧数据中的非法值按账号材料生成一次，后续 Token 轮换和重启继续使用同一值。没有账号级标识时不再共用全局 `machineId`。

后台明确提交非法的设备标识会返回错误，避免其他字段已经修改后才发现身份无效。替换刷新凭据不会隐式替换设备标识；如确实需要更换，请显式提交有效账号级值。

同一 OAuth 账号仍不能由多个独立代理实例无协调地同时刷新。本次修改的锁和状态仍以单个实例为边界。

## 限流与并发

| 配置 | 默认值 | 生效方式 |
| --- | --- | --- |
| `maxRpmPerCredential` | 10 | 启动/环境变量或管理设置热修改；0 显式关闭 RPM 保护 |
| `maxConcurrentRequests` | 20 | 重启 |
| `maxConcurrentPerCredential` | 2 | 重启 |
| `upstreamAdmissionTimeoutSecs` | 30 秒 | 重启 |

这些是部署默认值，不代表上游允许的配额。旧配置未写这些字段时会采用新默认值；显式的 RPM=0 保留原有不限行为。

RPM 在每次实际发送前原子预占，失败及重试也消耗窗口，避免并发读计数后一起越过上限。账号繁忙、RPM 已满或冷却时不会占用全局生成许可等待。单账号池也必须遵守上限，等待超过准入时限会返回 429 和 `Retry-After`。

全局和账号许可随上游响应体移动，直到完整读取、错误或取消/丢弃才释放，覆盖实时 SSE、普通响应和 MCP 请求。正常完整读完 HTTP 响应体后才记录调用成功；这表示传输完成，不保证模型输出满足业务预期。

上游 429 的 `Retry-After`（秒数或 HTTP 日期）会形成账号冷却，期间不能通过换同一账号的另一个端点继续发送。轮询保留每账号和总请求重试预算；本地准入、端点冷却耗尽也返回可识别的限流错误。

## 自动禁用与恢复

自动禁用后不会因为全池不可用或月份变化而直接启用。账号先保持禁用，冷却到期后使用 Token/额度只读接口验证；只有返回可用、未过期的正额度时才重新加入账号池。验活不发送模型推理请求，因此它验证认证和额度，不能保证某个模型的实际生成权限。

| 配置 | 默认值 |
| --- | --- |
| `accountRecoveryCooldownSecs` | 首次等待 300 秒 |
| `accountRecoveryMaxCooldownSecs` | 失败后退避上限 3600 秒 |
| `accountRecoveryProbeTimeoutSecs` | 单次验活总超时 30 秒 |

后台每 30 秒检查一次到期账号，每轮最多顺序探测 4 个。失败或超时继续禁用，并增加指数退避。下一次验活时间、失败次数和禁用原因随统计状态保存，重启后延续；旧自动禁用记录没有时间戳时也要先冷却。

手动禁用、已识别的刷新凭据永久失效，以及缺失必要身份配置的账号不参与自动恢复。管理员可以显式处理这些账号。自动验活同一账号只允许一个在途任务；管理员启停、修改或删除账号后，旧探测结果不能把它重新启用。

管理账号信息会显示冷却/验活状态及下次验活时间。修改并发和恢复时间配置需重启；所有时间设置须为 1～604800 秒，最大退避不能小于首次冷却，两个并发上限必须大于零。

环境变量名称见 `server.env.example`。不要把真实 Token、账号配置或私钥提交到仓库。
