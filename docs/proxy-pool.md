# 代理池与账号稳定绑定

管理员侧边栏的「代理列表」可以批量导入、检测、启停和删除代理，查看最近观测到的出口 IP、延迟和账号绑定。代理认证只用于连接，列表接口不会返回明文用户名或密码，导入窗口关闭或提交完成后清空输入。

## 导入格式

每行一条，默认使用 HTTP 代理：

```text
gateway.example:10001:demo-user:demo~password
gateway.example:10002:demo-user:demo~password:with-colon
```

密码中的 `~` 和额外冒号保持原样。也支持 HTTP、HTTPS、SOCKS5/SOCKS5H URL；URL 里的认证会被拆分到私密字段，公开地址不含认证。重复的地址与认证组合会跳过，不覆盖已有记录；非法行只返回行号和通用错误。

认证存储于配置目录的 `proxies.json`，使用原子写入和 Unix 0600 文件权限。该文件不应进入 Git、公开日志或浏览器持久化存储。

## 自动分配

第一次导入代理后启用托管策略。新账号没有显式指定独立代理时，会在首次 Token 验证之前分配一条健康代理。优先选择没有账号绑定的代理；不足时共享绑定较少的代理。绑定健康时保持稳定，不因普通轮询重新分配。

原有账号级独立代理和显式 `direct` 设置继续保留。代理池从未配置时保持原有全局代理行为；一旦配置过，即使所有代理被删除或停用，也不会把托管账号静默切到直连。没有可用代理时暂停转发，等待检测恢复或补充代理。

绑定的是代理网关配置。固定同一网关、端口和认证不保证供应商始终提供同一个出口 IP；代理列表的 IP 是最近健康检查的观测值。本功能不会改写供应商用户名中的地区或会话参数。

## 检测和故障切换

默认通过代理访问 `https://checkip.amazonaws.com/`，检查 HTTPS 连通性和有效 IP 响应，不携带 Kiro 账号凭据或发送模型请求。检测最多同时 4 条，容量等待与实际网络检测分别最多 10 秒，自动每轮最多 25 条；排队超时属于无法确认，不触发故障切换。健康代理按默认 300 秒间隔重新检测，故障代理默认冷却 60 秒。点击检测会异步执行，页面显示结果。

连接、代理认证或传输故障会触发有界健康确认。只有确认代理不可用，才为受影响账号寻找另一条健康代理。上游模型的认证失败、额度耗尽、429 和普通 5xx 不直接判定为代理故障；账号 RPM、Retry-After 和禁用状态不会因换代理清零。

检测排队、取消或其他无法确认的情况不会直接把健康代理标记为故障。探测完成时会核对代理版本，管理员停用、删除或修改后的旧结果不能使代理重新可用。切换账号绑定也会核对身份和旧绑定，避免覆盖管理员手动编辑。

已经输出内容的 SSE 中断不会自动重放。故障确认和切换供后续请求使用；客户端取消不触发代理故障判定。

## 配置

| 字段 | 默认值 |
| --- | --- |
| `proxyHealthCheckUrl` | `https://checkip.amazonaws.com/` |
| `proxyHealthCheckTimeoutSecs` | 容量等待与网络探测分别 10 秒，上限各 10 秒 |
| `proxyHealthCheckIntervalSecs` | 300 秒 |
| `proxyHealthCheckConcurrency` | 4，上限 4 |
| `proxyFailureCooldownSecs` | 60 秒 |

配置修改后重启生效，环境变量名称见 `server.env.example`。健康目标必须使用 HTTPS，不能包含用户名、密码、查询参数或片段。公网连通性检查成功并不等于某个 Kiro 模型的权限或生成请求已经通过验证。
