# admin-usage-log Specification

## Purpose

为 admin-ui「使用日志」页（原「每日统计」页）提供时间维度视图切换：固定区间汇总、当日明细与自定义区间明细，满足「快速看今天」与「任意时间段核对」两类高频诉求。

## Requirements

### Requirement: 使用日志页命名

The system SHALL 在 admin-ui 侧边栏、页面标题与面包屑中将原「每日统计」入口与页面统一改名为「使用日志」（英文 Usage Log），其余导航行为不变。

#### Scenario: 侧边栏入口改名
- **WHEN** 用户展开 admin-ui 侧边栏
- **THEN** 原「每日统计」菜单项显示为「使用日志」，图标与点击行为（进入该页面）不变

#### Scenario: 页面标题联动
- **WHEN** 用户进入该页面或从该页进入单日明细页
- **THEN** 页面标题与面包屑中的「每日统计」字样均显示为「使用日志」，英文界面显示「Usage Log」

### Requirement: 今日 Tab 默认展示当日明细

The system SHALL 在使用日志页的区间切换控件中新增「今日」tab 并作为默认选中项，选中时直接展示今天（CST 时区）的请求明细记录表。

#### Scenario: 默认进入即见今日明细
- **WHEN** 用户进入使用日志页（未手动切换过 tab）
- **THEN** 「今日」tab 处于选中态，主区展示今天的请求明细记录表（列结构与现有单日明细页一致：时间/IP/账号/模型/Token 用量/用时/费用/Credits）
- **AND** 明细表带服务端分页（每页 100 条），汇总卡按当前页数据计算并标注「当页」口径

#### Scenario: 今日无记录
- **WHEN** 今天尚无任何请求记录
- **THEN** 明细表展示空状态（与现有明细页空态一致），不出现报错

#### Scenario: 跨 CST 午夜自动切换
- **WHEN** 页面驻留期间跨越 CST 午夜
- **THEN** 「今日」明细的查询日期随现有 60s 轮询刷新为新的 CST 日期（与现有 today 汇总口径一致）
- **AND** 分页页码重置回第 1 页，避免停留在已越界的旧页码

### Requirement: 自定义时间段查询

The system SHALL 提供「自定义」tab，点击后弹出起止日期选择对话框，用户选择起始与结束日期并应用后，主区展示该闭区间内（from ≤ date ≤ to，CST 时区）的全部请求明细记录。

#### Scenario: 打开自定义对话框
- **WHEN** 用户在非自定义态点击「自定义」tab
- **THEN** 弹出起止日期选择对话框，含「起始日期」与「结束日期」两个日期输入及「应用」按钮
- **AND** 此时尚未应用任何区间，主区不展示空明细（保持前一 tab 内容直至应用或取消）

#### Scenario: 应用合法区间
- **WHEN** 用户选择起始日期 2026-10-01、结束日期 2026-10-07 并点击「应用」
- **THEN** 对话框关闭，主区展示 2026-10-01 至 2026-10-07（含两端）的请求明细记录，tab 保持「自定义」选中态并展示所选区间摘要

#### Scenario: 拒绝非法区间
- **WHEN** 用户设置的起始日期晚于结束日期（或任一日期为空）并点击「应用」
- **THEN** 前端提示起止日期不合法，不发起查询、不关闭对话框

#### Scenario: 后端校验非法参数
- **WHEN** API 收到 `from > to` 或格式非 `YYYY-MM-DD` 的请求
- **THEN** 返回 400 错误与明确错误信息（格式错误与 from>to 分别提示），不执行查询

#### Scenario: 区间记录数超上限
- **WHEN** 自定义区间内匹配记录超过 10000 条
- **THEN** 按时间降序排序后保留最新 10000 条（单日明细端点维持既有 2000 条上限不变，仅区间端点为 10000），total 与分页均基于截断后的数量，前端展示「仅展示最近 10000 条」提示

#### Scenario: 取消或关闭对话框
- **WHEN** 用户打开自定义对话框后未点击「应用」而直接关闭（点击遮罩 / ESC / 取消）
- **THEN** Segmented 应回退到点击「自定义」前所在的 tab，主区内容不变，不发起任何查询

#### Scenario: 自定义态的重开与保留
- **WHEN** 自定义区间已应用（明细展示中），用户切到其他 tab 后再点回「自定义」
- **THEN** 直接展示已应用区间的明细，不重新弹窗；区间选择状态保持
- **AND** 刷新页面后回到默认「今日」tab（自定义区间不持久化）

### Requirement: 区间明细查询端点

The system SHALL 提供 `GET /api/admin/usage/records?from=YYYY-MM-DD&to=YYYY-MM-DD&page=N&page_size=M` 端点，返回区间内请求明细（服务端分页），响应结构与现有按日明细端点一致（含 credential_label、credits_used、user_agent 等字段）。

#### Scenario: 区间含边界日
- **WHEN** 查询 from=2026-10-01、to=2026-10-03，且三天均有记录
- **THEN** 返回记录同时覆盖 10-01、10-02、10-03 三天（CST 口径），按时间降序排列

#### Scenario: 分页行为
- **WHEN** 区间内共 350 条记录且 page_size=100
- **THEN** 返回 total=350、totalPages=4，page=2 时返回第 101–200 条

#### Scenario: page_size 越界钳制
- **WHEN** 请求 page_size=9999 或 page_size=0
- **THEN** page_size 被钳制到 [1, 500]（与现有按日明细端点一致）
